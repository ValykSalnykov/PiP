# Подання DAO Tools+ до Chrome Web Store

## Короткий опис

```text
DAO Tools+ для Planfix/Syrve: автологін, ліцензії, PiP та заявки HelpDesk зі скріншотом.
```

## Повний опис

```text
DAO Tools+ — внутрішнє робоче розширення компанії DAO для співробітників і підрядників, які працюють з DAO Planfix, Syrve та внутрішніми DAO веб-сервісами.

Розширення об'єднує кілька робочих сценаріїв в одному інтерфейсі:
- додає в DAO Planfix кнопки та статуси для швидкого входу в legacy backoffice Syrve, відкриття Web: посилання окремою кнопкою Веб і окремої кнопки Веб:API для сторінки integrations, запуску Loyalty, підготовки й автозаповнення чернетки HelpDeskEddy, перевірки доступності сервера, отримання відкритого періоду з версією Syrve, перевірки стану ліцензій та запуску масових ліцензійних операцій;
- відкриває робочі сторінки Syrve як на legacy-доменах /resto, так і на доменах *.syrve.app, і автоматично підставляє видані компанією облікові дані лише для погодженого користувача та схваленого пристрою; для нового Web flow URL читається прямо з поля Web: посилання в картці Planfix;
- на службовій сторінці зайнятих ліцензій Syrve для серверів, які не належать до syrve.online, після явного кліку користувача відкриває /resto/service/maintance/groovy.jsp на тому самому сервері, через одноразовий токен передає локально вбудований Groovy-скрипт скидання модулів 100/101 або 200 і повертається до таблиці для перевірки результату;
- відкриває внутрішню сторінку Loyalty і автоматично підставляє логін із картки Planfix та службовий пароль компанії;
- відкриває чернетку HelpDeskEddy і переносить у форму потрібні службові поля із задачі Planfix; для сценарію завислої ліцензії після явного кліку користувача просить Chrome показати системний вибір екрана, додає скріншот у HelpDeskEddy для https://*.syrve.online/resto/service/monitoring/connections.jsp, а для інших серверів використовує HelpDesk як fallback після невдалого автоматичного скидання, якщо сторінку відкрито з Planfix-контекстом;
- через popup дає змогу зберегти User ID, запросити персональний доступ для пристрою, активувати його кодом підтвердження, побачити поточний стан доступу, надіслати server context, прочитати або перемкнути режим і вручну показати останню діагностичну помилку;
- через popup також зберігає вигляд відображення ліцензій, поріг визначення завислих ліцензій і налаштування підсвічування нових або прострочених задач для інтерактивного PiP-вікна;
- запускає вбудований інтерактивний Picture-in-Picture на внутрішніх DAO веб-сторінках на доменах hub.daolog.net і *.us-central1.hosted.app, у тому числі за клавіатурною командою.

Розширення призначене лише для внутрішніх робочих завдань DAO. Воно не призначене для загального веб-серфінгу, не впроваджує віддалений код і не змінює поведінку сайтів поза робочими доменами та конкретними Syrve-серверами, для яких користувач явно запускає службову дію.
```

## Обґрунтування дозволів

### alarms

```text
Дозвіл alarms використовується для фонового оновлення статусу доступності DAO backend приблизно раз на хвилину в service worker. Розширення запускає періодичну перевірку, зберігає останній статус у локальному storage і оновлює індикатор action та дані popup без потреби тримати відкриту сторінку або popup.
```

### tabs

```text
Дозвіл tabs використовується для робочих сценаріїв усередині DAO Tools+: розширення відкриває і за потреби закриває службові вкладки Syrve, *.syrve.app, Loyalty, HelpDeskEddy та тимчасові службові вкладки для отримання відкритого періоду й версії, отримує поточну активну вкладку для перемикання Picture-in-Picture, надсилає повідомлення між service worker і content scripts, а також оновлює індикатор action для PiP і службових станів.
```

### storage

```text
Дозвіл storage використовується для локального зберігання робочих налаштувань і стану доступу пристрою: User ID, згенерованого client ID пристрою, request ID, персонального extension key, списку дозволених прав доступу, формату масових ліцензійних операцій, службового повідомлення про стан доступу, останнього server context, timestamp останнього ручного запиту popup-діагностики, збережених описів режимів popup, вибраного вигляду ліцензій, порогу визначення завислих ліцензій, налаштувань підсвічування завдань PiP і тимчасового стану та лічильника чернеток HelpDeskEddy. Тимчасово в chrome.storage.session також зберігаються скріншоти для вкладення в HelpDeskEddy і одноразові запити Groovy-скидання, а в sessionStorage вкладки connections.jsp коротко зберігається прапорець перевірки результату скидання після перезавантаження сторінки. Це потрібно, щоб не вимагати повторного введення, зберігати робочий контекст між сеансами та підтримувати cooldown ручного запиту останньої помилки між відкриттями popup. Паролі Syrve в chrome.storage не зберігаються.
```

### desktopCapture

```text
Дозвіл desktopCapture використовується лише після явного кліку користувача на сторінці зайнятих ліцензій Syrve для сценарію завислої ліцензії. Chrome показує системний вибір екрана, користувач має вручну обрати джерело захоплення, після чого розширення створює один JPEG-скріншот. Для https://*.syrve.online/resto/service/monitoring/connections.jsp скріншот тимчасово передається в чернетку HelpDeskEddy як вкладення; для інших серверів скріншот використовується у fallback HelpDesk-сценарії після невдалого автоматичного скидання, якщо є Planfix-контекст. Розширення не записує відео й не запускає захоплення екрана у фоні.
```

## Готові тексти для Privacy practices

### Single purpose

```text
DAO Tools+ забезпечує один внутрішній робочий потік для співробітників DAO між DAO Planfix, Syrve, Loyalty, HelpDeskEddy та внутрішніми DAO сервісами: персональний доступ пристрою, автологін, відкриття службових сторінок, перевірка доступності й ліцензій, оновлення ліцензій, підготовка чернеток HelpDeskEddy і Picture-in-Picture для внутрішніх DAO сторінок.
```

### Remote code

```text
No. DAO Tools+ does not execute remote JavaScript or remote extension logic. All executable JavaScript and CSS are packaged with the extension. Remote services return only data such as JSON, text status messages, credentials for approved users/devices, and license operation results; these responses are not evaluated or executed as code. The Groovy maintenance script used for stale-license reset is packaged in the extension and limited to module IDs 100/101 and 200.
```

### Data usage certification

```text
DAO Tools+ uses collected data only to provide its internal DAO workflow features described in the listing and extension UI. The extension does not sell user data, does not use user data for advertising or credit decisions, and does not transfer data except where necessary to operate DAO backend services, Syrve, Loyalty, and HelpDeskEddy workflows requested by the user. Screen capture is used only after an explicit user action and Chrome's source picker, to attach one screenshot to a HelpDeskEddy draft for a stale-license support case.
```

## Технічний статус для рев'ю

```text
Захищений DAO backend опублікований на https://slm.daolog.net з актуальним TLS-сертифікатом. Чутливі робочі операції, зокрема request/claim потоки, extension key, перевірка стану доступу пристрою, видача облікових даних Syrve, CRM handoff, перевірки доступності, перевірки ліцензій і оновлення ліцензій, ідуть лише по HTTPS.

Внутрішній popup/backend на https://planfix-to-syrve.com:8000 використовується тільки для send_data, get_mode_description, toggle_mode і get_last_error; запит get_last_error виконується лише вручну з popup, а локальний cooldown цього запиту зберігається між відкриттями popup через chrome.storage.

Поточний Web flow більше не використовує окремий lookup веб-адреси на backend: розширення читає поле Web: посилання прямо з картки Planfix, відкриває відповідний *.syrve.app URL окремою кнопкою Веб і за потреби окремою кнопкою Веб:API відкриває integrations-сторінку /integration-management/index.html#/integrations, після чого виконує автологін на боці розширення.

Кнопка Довідники використовує той самий Web hostname, але не отримує логін і пароль у браузер для цієї операції: розширення викликає захищений маршрут /crm/handoff на SLM, а SLM бере першу активну service account, звертається до зовнішнього CRM API й повертає тільки перевірене одноразове посилання https://api.daolog.net/connect?ticket=....
```
