# Подання DAO Tools+ до Chrome Web Store

## Короткий опис

```text
Інструменти DAO для Planfix і Syrve: автологін, перевірка й оновлення ліцензій, PiP та службові дії в картках.
```

## Повний опис

```text
DAO Tools+ — внутрішнє робоче розширення компанії DAO для співробітників і підрядників, які працюють з DAO Planfix, Syrve та внутрішніми DAO веб-сервісами.

Розширення об'єднує кілька робочих сценаріїв в одному інтерфейсі:
- додає в DAO Planfix кнопки та статуси для швидкого входу в legacy backoffice Syrve, відкриття Web: посилання окремою кнопкою Веб і окремої кнопки Веб:API для сторінки integrations, запуску Loyalty, підготовки й автозаповнення чернетки HelpDeskEddy, перевірки доступності сервера, отримання відкритого періоду з версією Syrve, перевірки стану ліцензій та запуску масових ліцензійних операцій;
- відкриває робочі сторінки Syrve як на legacy-доменах /resto, так і на доменах *.syrve.app, і автоматично підставляє видані компанією облікові дані лише для погодженого користувача та схваленого пристрою; для нового Web flow URL читається прямо з поля Web: посилання в картці Planfix;
- відкриває внутрішню сторінку Loyalty і автоматично підставляє логін із картки Planfix та службовий пароль компанії;
- відкриває чернетку HelpDeskEddy, переносить у форму потрібні службові поля із задачі Planfix та повертає статус заповнення назад у Planfix;
- через popup дає змогу зберегти User ID, запросити персональний доступ для пристрою, активувати його кодом підтвердження, побачити поточний стан доступу, надіслати server context, прочитати або перемкнути режим і вручну показати останню діагностичну помилку;
- через popup також зберігає вигляд відображення ліцензій і налаштування підсвічування нових або прострочених задач для інтерактивного PiP-вікна;
- запускає вбудований інтерактивний Picture-in-Picture на внутрішніх DAO веб-сторінках на доменах hub.daolog.net і *.us-central1.hosted.app, у тому числі за клавіатурною командою.

Розширення призначене лише для внутрішніх робочих завдань DAO. Воно не призначене для загального веб-серфінгу, не впроваджує віддалений код і не змінює поведінку сайтів поза переліченими робочими доменами.
```

## Обґрунтування дозволів

### alarms

```text
Дозвіл alarms використовується для фонового оновлення статусу доступності DAO backend приблизно раз на хвилину в service worker. Розширення запускає періодичну перевірку, зберігає останній статус у локальному storage і оновлює індикатор action та дані popup без потреби тримати відкриту сторінку або popup.
```

### tabs

```text
Дозвіл tabs використовується для робочих сценаріїв усередині DAO Tools+: розширення відкриває і за потреби закриває службові вкладки Syrve, *.syrve.app, Loyalty, HelpDeskEddy та тимчасові службові вкладки для отримання відкритого періоду й версії, отримує поточну активну вкладку для перемикання Picture-in-Picture, надсилає повідомлення між service worker і content scripts, а також оновлює індикатор action для PiP і службових станів.
```

### storage

```text
Дозвіл storage використовується для локального зберігання робочих налаштувань і стану доступу пристрою: User ID, згенерованого client ID пристрою, request ID, персонального extension key, списку дозволених прав доступу, формату масових ліцензійних операцій, службового повідомлення про стан доступу, останнього server context, timestamp останнього ручного запиту popup-діагностики, збережених описів режимів popup, вибраного вигляду ліцензій, налаштувань підсвічування завдань PiP і тимчасового стану та лічильника чернеток HelpDeskEddy. Це потрібно, щоб не вимагати повторного введення, зберігати робочий контекст між сеансами та підтримувати cooldown ручного запиту останньої помилки між відкриттями popup. Паролі Syrve в chrome.storage не зберігаються.
```

### desktopCapture

```text
Дозвіл desktopCapture використовується лише після явного кліку користувача на сторінці зайнятих ліцензій Syrve для створення чернетки HelpDeskEddy щодо завислої ліцензії. Chrome показує системний вибір екрана, користувач має вручну обрати весь екран, після чого розширення створює один JPEG-скріншот і тимчасово передає його в чернетку HelpDeskEddy як вкладення. Якщо користувач скасовує вибір екрана, заявка не створюється.
```

## Віддалений код

```text
Ні. Усі JavaScript- і CSS-файли, які виконує розширення, постачаються всередині пакета розширення. Мережеві відповіді від https://slm.daolog.net і https://planfix-to-syrve.com:8000 використовуються лише як JSON або текстові дані для режимів, повідомлень і результатів службових операцій та не виконуються як код розширення.
```

## Що розширення реально обробляє

```text
- локально зберігає User ID, client ID пристрою, request ID, extension key, права доступу пристрою, формат масових ліцензійних операцій, службове повідомлення про стан доступу, last server context, timestamp останнього ручного popup-запиту останньої помилки, список відомих описів режимів popup, вигляд відображення ліцензій, налаштування підсвічування завдань PiP і тимчасовий стан та лічильник внутрішніх чернеток HelpDeskEddy;
- надсилає на захищений DAO backend User ID, client ID пристрою та назву пристрою для запиту доступу; request ID і claim code для активації; X-Extension-Key і X-User-Id для захищених маршрутів; адресу сервера, порт, а за потреби batch ID і UID або serial лише для сценаріїв availability, license check і license update;
- надсилає на внутрішній popup/backend client_id і server context для службових popup-операцій send_data, читання або перемикання режиму та ручного отримання останньої помилки;
- отримує із захищеного DAO backend логін і пароль Syrve для схваленого користувача та пристрою, тимчасово тримає їх у пам'яті вкладки та підставляє у форму авторизації Syrve на legacy /resto і *.syrve.app сторінках;
- використовує логін Loyalty з картки Planfix та службовий пароль компанії, щоб автоматично заповнити сторінку loyalty.syrve.live;
- читає з Planfix лише ті поля, які потрібні для конкретної дії: адресу або порт сервера, Web: посилання, логін Loyalty, поля задачі для HelpDeskEddy, CRMID, версію Syrve та інші службові значення, які прямо відображаються в чернетці або ліцензійному статусі;
- заповнює чернетку HelpDeskEddy значеннями з Planfix і повертає результат заповнення назад у вкладку Planfix;
- читає зі службової сторінки Syrve значення відкритого періоду та версії і повертає результат в інтерфейс Planfix;
- читає зі службової сторінки Syrve зайнятих ліцензій лише колонку Last activity і локально підкреслює рядки, де активність відстає від поточного часу більше заданого порогу;
- після ручного вибору користувачем у Chrome desktop picker створює один скріншот екрана для вкладення в чернетку HelpDeskEddy щодо завислої ліцензії; скріншот тимчасово зберігається в chrome.storage.session і очищається після завершення або помилки заповнення чернетки;
- передає локальні налаштування PiP-підсвічування на внутрішні DAO сторінки hub.daolog.net і *.us-central1.hosted.app через chrome.storage.
```

## Технічний статус для рев'ю

```text
Захищений DAO backend опублікований на https://slm.daolog.net з актуальним TLS-сертифікатом. Чутливі робочі операції, зокрема request/claim потоки, extension key, перевірка стану доступу пристрою, видача облікових даних Syrve, перевірки доступності, перевірки ліцензій і оновлення ліцензій, ідуть лише по HTTPS.

Внутрішній popup/backend на https://planfix-to-syrve.com:8000 використовується тільки для send_data, get_mode_description, toggle_mode і get_last_error; запит get_last_error виконується лише вручну з popup, а локальний cooldown цього запиту зберігається між відкриттями popup через chrome.storage.

Поточний Web flow більше не використовує окремий lookup веб-адреси на backend: розширення читає поле Web: посилання прямо з картки Planfix, відкриває відповідний *.syrve.app URL окремою кнопкою Веб і за потреби окремою кнопкою Веб:API відкриває integrations-сторінку /integration-management/index.html#/integrations, після чого виконує автологін на боці розширення.

Для масових ліцензійних операцій розширення або виконує inline-чергу через захищений DAO backend, або в legacy-форматі відкриває окрему робочу сторінку license manager у новій вкладці; у жодному з цих сценаріїв мережеві відповіді не виконуються як код розширення. Це відповідає поточним URL і сценаріям у manifest.json, background.js, popup.js і content scripts.
```
